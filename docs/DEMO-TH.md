# คู่มือสาธิตและดูแลระบบ Rescue

เอกสารนี้ใช้สำหรับสาธิตลำดับงานจริง ตั้งแต่ประชาชนแจ้งเหตุผ่าน LINE จนเจ้าหน้าที่ปิดภารกิจ รวมถึงการดูแลข้อมูลเดโมอย่างปลอดภัย

ขั้นตอนติดตั้ง การตั้งค่า `.env`, LINE LIFF/OA, MySQL, Redis และ URL ของแต่ละส่วนอยู่ใน [คู่มือส่งมอบระบบ](./HANDOFF-TH.md) เอกสารนี้ไม่ทำซ้ำขั้นตอนเหล่านั้น

> ระบบนี้เป็นโครงงานสาธิต ไม่ใช่ช่องทางฉุกเฉินที่ผ่านการรับรอง หากเป็นเหตุจริงให้ติดต่อหน่วยฉุกเฉินในพื้นที่ เช่น 1669

## บทบาทและหน้าจอ

ระบบมี 3 บทบาทที่ต่างกัน

- **ประชาชน (Citizen):** เปิดหน้าหลัก `/` ผ่าน LINE LIFF ใช้บัญชี LINE จริง ยืนยันเบอร์โทร แจ้งเหตุ และติดตามรถกู้ภัย
- **เจ้าหน้าที่กู้ภัย (Rescue):** เข้าระบบที่ `/login` ของเว็บประชาชน แล้วทำงานที่ `/dashboard` ต้องได้รับอนุมัติจากผู้ดูแลก่อน
- **ผู้ดูแลระบบ (Admin):** เข้าระบบที่ `/login` ของเว็บแอดมิน แล้วดูภาพรวมที่ `/dashboard` จัดการมูลนิธิและบัญชีกู้ภัย รวมถึงบังคับยกเลิกเคส

เพื่อให้การสาธิตเห็นทุกจุดพร้อมกัน ควรใช้ 3 หน้าจอหรือ 3 โปรไฟล์เบราว์เซอร์แยกกัน ใช้บัญชีกู้ภัยคนละบัญชีต่ออุปกรณ์ เพราะสถานะออนไลน์ผูกกับการเชื่อมต่อปัจจุบันของบัญชีนั้น

## เตรียมก่อนเริ่มเดโม

1. เปิด backend, เว็บประชาชน, เว็บแอดมิน, MySQL และ Redis ตาม [คู่มือส่งมอบระบบ](./HANDOFF-TH.md)
2. เปิดเว็บแอดมินและเข้าสู่ระบบด้วยบัญชี Admin ของชุดเดโม
3. เปิด `/login` ของเว็บประชาชนบนอุปกรณ์เจ้าหน้าที่ แล้วเข้าสู่ระบบด้วยบัญชี Rescue ที่อนุมัติแล้ว
4. อนุญาตตำแหน่งบนอุปกรณ์เจ้าหน้าที่ รอให้แสดง `GPS ✓` แล้วกด **เริ่มปฏิบัติงาน** สถานะต้องเป็น **เปิดรับงานอยู่**
5. เปิด LIFF บน LINE ของอุปกรณ์ประชาชน อนุญาตตำแหน่ง และรอข้อความ **ได้รับตำแหน่งแล้ว**

อุปกรณ์ประชาชนกับเจ้าหน้าที่ต้องอยู่ห่างกันไม่เกิน 50 กิโลเมตรตามพิกัดที่อุปกรณ์รายงาน มิฉะนั้นระบบจะไม่ส่งงานให้อุปกรณ์เจ้าหน้าที่

## ลำดับสาธิต: LINE แจ้งเหตุจนปิดงาน

### 1. ประชาชนยืนยันตัวตนและเบอร์โทร

1. เปิด LIFF จาก LINE ไม่ใช่แท็บเบราว์เซอร์ทั่วไป หากเปิดผิดช่องทาง หน้าเว็บจะแสดงลิงก์ **เปิดใน LINE เพื่อแจ้งเหตุ**
2. ครั้งแรก ระบบยืนยันตัวตนกับ LINE แล้วแสดงหน้าต่าง **ลงทะเบียนครั้งแรก**
3. กรอกเบอร์โทร 9–10 หลักที่ขึ้นต้นด้วย `0` แล้วกด **บันทึกข้อมูลและเข้าสู่ระบบ**
4. ครั้งถัดไป ระบบดึงเบอร์โทรที่ผูกกับบัญชี LINE เดิมมาให้โดยอัตโนมัติ

บัญชีประชาชนไม่ใช่บัญชีชื่อผู้ใช้/รหัสผ่านในตาราง `users` และไม่ควรสร้างบัญชี LINE ปลอมเพื่อเดโม

### 2. ประชาชนส่ง SOS

1. กรอก **เกิดอะไรขึ้น** หรือจุดสังเกตตามสถานการณ์เดโม
2. ตรวจว่าแสดง **ได้รับตำแหน่งแล้ว** และปุ่ม SOS ใช้งานได้
3. กดปุ่ม **SOS** ค้าง 5 วินาที ปล่อยก่อนครบเวลาเพื่อยกเลิกได้
4. เมื่อส่งสำเร็จ หน้าจอแสดง **ส่งคำขอแล้ว กำลังค้นหาทีมกู้ภัย** พร้อม Tracking ID

ระบบส่งพิกัดที่อุปกรณ์วัดได้จริงเท่านั้น ไม่มีพิกัดสำรอง หากยังขอตำแหน่งไม่สำเร็จ ถูกปฏิเสธ หมดเวลา หรือพิกัดมีอายุ 60 วินาทีขึ้นไป ปุ่ม SOS จะถูกปิดและระบบจะไม่สร้างเคส ให้กด **ขอตำแหน่งอีกครั้ง** แล้วรอผลใหม่

### 3. เจ้าหน้าที่รับงาน

1. อุปกรณ์ Rescue ที่ออนไลน์และอยู่ในรัศมีจะเห็นหน้า **มีคำขอความช่วยเหลือใหม่**
2. ตรวจรายละเอียด แล้วกด **รับงาน (Accept)**
3. หากเจ้าหน้าที่คนอื่นรับก่อน ระบบจะแจ้งว่าเคสถูกทีมอื่นรับแล้ว การรับงานใช้การล็อกฝั่ง server จึงมีผู้ชนะเพียงคนเดียว
4. หลังรับงาน เจ้าหน้าที่เห็นหน้า **Active Mission** มีจุดเกิดเหตุ จุดรถกู้ภัย เส้นทาง เบอร์ผู้แจ้ง และช่องสนทนา

ปุ่ม **ข้ามเคสนี้** ปิดข้อเสนอบนอุปกรณ์นั้นเท่านั้น เคสยังคงรอเจ้าหน้าที่อื่น และอาจถูกเสนอใหม่หลังรอบกระจายงานถัดไป

### 4. ประชาชนติดตามความช่วยเหลือ

เมื่อเจ้าหน้าที่รับงาน หน้าประชาชนเปลี่ยนเป็น **ติดตามความช่วยเหลือ** และแสดงข้อมูลต่อไปนี้

- ชื่อและเบอร์โทรเจ้าหน้าที่ หากบัญชีกู้ภัยมีข้อมูลดังกล่าว
- ตำแหน่งประชาชนและตำแหน่งรถกู้ภัยบนแผนที่
- ระยะทางและเวลาโดยประมาณ เมื่อบริการคำนวณเส้นทางภายนอกตอบกลับ
- ปุ่มโทรหาเจ้าหน้าที่ ห้องสนทนา และการส่งรูปภาพประกอบ

ตำแหน่งรถอัปเดตผ่าน Socket.IO ขณะอุปกรณ์เจ้าหน้าที่ส่งพิกัดและยังเชื่อมต่ออยู่ การแจ้งเตือน LINE Push เป็นส่วนเสริม; การติดตามในแอปยังเป็น flow หลัก

### 5. เจ้าหน้าที่ปิดภารกิจ

1. ที่หน้า **Active Mission** กด **เสร็จสิ้นภารกิจ**
2. ยืนยันข้อความว่าช่วยเหลือเสร็จสิ้นแล้ว
3. ระบบเปลี่ยนเคสหลักและเคสกำลังเสริมในครอบครัวเดียวกันเป็น `Resolved`
4. หน้าประชาชนได้รับข้อความจบภารกิจและล้างเคสที่กำลังติดตาม
5. เจ้าหน้าที่กลับสู่สถานะพร้อมรับงานถัดไป และประวัติปรากฏในเว็บแอดมิน

## สิ่งที่ผู้ดูแลเห็นระหว่างเดโม

หน้า `/dashboard` ของเว็บแอดมินแสดงจำนวนเคส `Pending`, เคส `Accepted`, หน่วยที่เชื่อมต่อ แผนที่เคสและรถ รวมถึงรายการ **ข้อมูลเหตุฉุกเฉิน (Active Events)**

ผู้ดูแลไม่ใช่ผู้รับงานแทนเจ้าหน้าที่ หากต้องหยุดเคสผิดพลาด ให้กด **บังคับยกเลิกเหตุนี้ (Force Cancel)** เลือกเหตุผล แล้วกด **ยืนยันการยกเลิก** ระบบจะปิดเคสเป็น `Resolved`, เก็บเหตุผล และปล่อยเจ้าหน้าที่ที่เกี่ยวข้องกลับเป็นพร้อมใช้งาน

## ข้อจำกัด GPS และแผนที่

- การขอตำแหน่งบนเว็บต้องใช้ HTTPS หรือ `localhost` และต้องได้รับสิทธิ์จาก LINE/เบราว์เซอร์และระบบปฏิบัติการ
- พิกัดในอาคารอาจคลาดเคลื่อน ระบบไม่ได้รับรองความแม่นยำระดับการแพทย์หรือการนำทางฉุกเฉิน
- ตำแหน่งประชาชนต้องมีอายุน้อยกว่า 60 วินาทีทั้งตอนเริ่มและตอนครบการกดค้าง 5 วินาที หากอายุครบ 60 วินาทีระหว่างกด ระบบจะไม่ส่ง SOS
- เจ้าหน้าที่จะกด **เริ่มปฏิบัติงาน** ไม่ได้จนกว่าจะได้รับ GPS จริง
- การจับคู่ค้นหาเฉพาะเจ้าหน้าที่ออนไลน์ภายใน 50 กิโลเมตร และใช้เฉพาะ lease ที่มี heartbeat อายุน้อยกว่า 60 วินาที
- แผนที่ใช้ OpenStreetMap และเส้นทางใช้บริการ OSRM ภายนอก จึงต้องใช้อินเทอร์เน็ต การคำนวณเส้นทางล้มเหลวไม่ได้แปลว่าเคสหาย ให้ใช้รายละเอียดและพิกัดที่แสดงประกอบ

## การสร้างผู้ใช้และหน่วยงาน

### ทำผ่านหน้าเว็บได้

- **สร้างมูลนิธิ:** เว็บแอดมิน > **จัดการหน่วยกู้ภัย** > **เพิ่มมูลนิธิ/สังกัดใหม่**
- **สร้าง Rescue โดย Admin:** หน้าต่างเดียวกัน > **เพิ่มบัญชีรถกู้ภัย** สร้างทีละบัญชี หรือโหลดแบบฟอร์มและอัปโหลด CSV
- **สมัคร Rescue ด้วยตนเอง:** เว็บประชาชน > `/register` เลือกมูลนิธิ กรอกชื่อผู้ใช้ รหัสผ่าน และเบอร์โทร จากนั้น Admin เปิด **จัดการหน่วยกู้ภัย** > **รอการอนุมัติ** แล้วกด **อนุมัติ** หรือ **ลบ**
- **ประชาชน:** สร้างอัตโนมัติเมื่อยืนยันตัวตนผ่าน LINE LIFF ครั้งแรก แล้วบันทึกเบอร์โทรในหน้าต่างลงทะเบียน

### ต้องใช้คำสั่งหรือฐานข้อมูล

หน้าเว็บไม่มีฟังก์ชันสร้างบัญชี Admin, เปลี่ยนรหัสผ่าน Admin หรือลบบัญชีที่อนุมัติแล้ว ให้ใช้คำสั่งสร้าง Admin, seed ชุดเดโม และวิธีสร้าง password hash ที่ระบุใน [คู่มือส่งมอบระบบ](./HANDOFF-TH.md) เท่านั้น ห้ามบันทึกรหัสผ่านแบบข้อความธรรมดาลงฐานข้อมูล และห้ามคัดลอกบัญชีหรือข้อมูลจากระบบจริงมาใช้เดโม

## รีเซ็ตเดโมอย่างปลอดภัย

### รีเซ็ตเฉพาะเคสที่กำลังทำงาน

ใช้ UI ก่อนเสมอ เพื่อให้ฐานข้อมูล สถานะ Redis และหน้าจอทุกฝ่ายสอดคล้องกัน

1. เคส `Accepted`: ให้เจ้าหน้าที่ที่รับงานกด **เสร็จสิ้นภารกิจ**
2. เคส `Pending` หรือเคสที่อุปกรณ์เจ้าหน้าที่ใช้งานไม่ได้: ให้ Admin กด **บังคับยกเลิกเหตุนี้ (Force Cancel)** และเลือกเหตุผลที่ตรงจริง
3. รอให้รายการ Active Events หาย และให้เจ้าหน้าที่กลับสู่หน้าพร้อมรับงาน
4. หากหน้าประชาชนยังค้าง ให้รีเฟรชเพื่อให้ระบบอ่านสถานะล่าสุด ห้ามลบ `activeCitizenIncident` จาก local storage ขณะที่เคสยังเป็น `Pending` หรือ `Accepted`

วิธีนี้เก็บประวัติเดโมไว้สำหรับตรวจสอบและไม่ทำลายบัญชี

### เริ่มชุดเดโมใหม่โดยไม่ลบฐานเดิม

การสาธิตซ้ำตามปกติไม่ต้องล้างฐานข้อมูล ใช้ปุ่ม **เสร็จสิ้นภารกิจ** หรือ **Force Cancel** ตามหัวข้อก่อนหน้า ประวัติที่เหลืออยู่ช่วยยืนยันว่า flow ทำงานครบ

หากต้องการฐานว่างจริง ให้สร้าง Docker Compose project ใหม่แทนการรัน `DELETE`, `DROP`, `FLUSHDB` หรือ `down -v` กับ project เดิม วิธีนี้เก็บ volume เดิมไว้ย้อนกลับได้:

1. ปิดหน้าเว็บทุกบทบาทและหยุด process backend เพื่อไม่ให้ polling หรือ Socket.IO เขียนระหว่างสลับฐาน
2. สำรองฐานเดิมตามหัวข้อถัดไป
3. เข้าไดเรกทอรี `rescue-backend` แล้วหยุด project เดิมโดย **ห้าม** ใส่ `-v`:

   ```bash
   docker compose -p rescue-classroom down
   ```

4. สร้างชื่อ project ใหม่ที่ไม่เคยใช้ แล้วเปิด MySQL และ Redis จาก `.env` เดิม พอร์ตเดิมใช้ได้เพราะ project เดิมหยุดแล้ว:

   ```bash
   fresh_project="rescue-classroom-fresh-$(date +%Y%m%d%H%M%S)"
   docker compose -p "$fresh_project" up -d mysql redis
   docker compose -p "$fresh_project" ps
   ```

   Compose จะสร้าง volume MySQL ใหม่และรัน `schema.sql` อัตโนมัติ ฐานเดิมของ project `rescue-classroom` ยังอยู่

5. ใช้คำสั่ง seed บัญชีเดโมจาก [คู่มือส่งมอบระบบ](./HANDOFF-TH.md) กับ project ใหม่เท่านั้น แล้วเริ่ม backend ตามปกติ
6. หากต้องการกลับฐานเดิม ให้หยุด backend และ project ใหม่ก่อน จากนั้นเปิด project เดิม:

   ```bash
   docker compose -p "$fresh_project" down
   docker compose -p rescue-classroom up -d mysql redis
   ```

ตัวแปร `fresh_project` มีผลเฉพาะ shell ปัจจุบัน จดชื่อ project ที่แสดงจากคำสั่ง `docker compose ls` ไว้ก่อนปิด terminal ห้ามใช้ `docker compose down -v` จนกว่าจะยืนยันว่า volume นั้นไม่ต้องใช้อีก

## สำรองและกู้คืนข้อมูลเดโม

ใช้บัญชีฐานข้อมูลที่มีสิทธิ์เฉพาะฐานเดโม และเก็บไฟล์สำรองนอก Git เพราะอาจมีเบอร์โทร, LINE UID, token ของเคส และข้อความสนทนา คำสั่งด้านล่างใช้ client ภายใน MySQL 8 container จึงไม่ต้องติดตั้ง `mysql` หรือ `mysqldump` บนเครื่อง

### สำรอง project ค่าเริ่มต้น

เข้าไดเรกทอรี `rescue-backend` ซึ่งมี `.env` และ `docker-compose.yml` แล้วรัน:

```bash
umask 077
backup_dir="$(mktemp -d "${TMPDIR:-/tmp}/rescue-backups.XXXXXX")"
backup_file="$backup_dir/rescue-demo-$(date +%Y%m%d-%H%M%S).sql"

docker compose -p rescue-classroom exec -T mysql sh -c \
  'MYSQL_PWD="$MYSQL_PASSWORD" exec mysqldump -u"$MYSQL_USER" \
  --single-transaction --no-tablespaces --set-gtid-purged=OFF \
  --default-character-set=utf8mb4 "$MYSQL_DATABASE"' \
  > "$backup_file" &&
  test -s "$backup_file" && chmod 600 "$backup_file" && echo "$backup_file"
```

รหัสผ่านมาจาก environment ภายใน container และไม่ถูกเขียนลงคำสั่งหรือไฟล์ dump คำสั่งไม่ใช้ `--databases` ดังนั้น dump ไม่มี `CREATE DATABASE` หรือ `USE` ที่อาจพาไปเขียนฐานอื่นโดยไม่ตั้งใจ

ไดเรกทอรีจาก `mktemp` อยู่นอก repository และมีสิทธิ์จำกัด แต่พื้นที่ชั่วคราวอาจถูกระบบล้าง ให้ย้ายไฟล์ไปยังที่เก็บถาวรซึ่งเข้ารหัสหรือจำกัดสิทธิ์ และบันทึก path ก่อนปิด shell ห้ามเพิ่มไฟล์ `.sql` นี้เข้า Git

### กู้คืนเข้า project ใหม่เท่านั้น

อย่ากู้ทับ project `rescue-classroom` เดิม ให้หยุด backend และเปิด project ใหม่ที่มี volume ใหม่ตามขั้นตอนนี้จาก `rescue-backend`:

```bash
docker compose -p rescue-classroom down

restore_project="rescue-restore-$(date +%Y%m%d%H%M%S)"
docker compose -p "$restore_project" up -d mysql redis
docker compose -p "$restore_project" ps

docker compose -p "$restore_project" exec -T mysql sh -c \
  'MYSQL_PWD="$MYSQL_PASSWORD" exec mysql -u"$MYSQL_USER" "$MYSQL_DATABASE"' \
  < "/absolute/path/to/rescue-demo-YYYYMMDD-HHMMSS.sql"
```

คำสั่ง `down` ด้านบนไม่มี `-v` จึงเก็บ volume เดิมไว้ หลัง `up -d` ให้ดู `docker compose -p "$restore_project" logs mysql` และรอข้อความ `ready for connections` ก่อนรันคำสั่ง restore เปลี่ยน path บรรทัดสุดท้ายให้เป็นไฟล์ backup จริง แล้วตรวจ project กู้คืนก่อนนำไปใช้:

```bash
docker compose -p "$restore_project" exec -T mysql sh -c \
  'MYSQL_PWD="$MYSQL_PASSWORD" exec mysql -u"$MYSQL_USER" "$MYSQL_DATABASE" \
  -e "SELECT COUNT(*) AS users_count FROM users; SELECT COUNT(*) AS incidents_count FROM incidents;"'
```

เริ่ม backend ด้วย `.env` เดิมเพื่อทดสอบกับ project กู้คืน ซึ่งใช้พอร์ตเดิมหลัง project ต้นฉบับหยุดแล้ว เมื่อต้องการกลับฐานเดิม ให้หยุด backend แล้วรัน:

```bash
docker compose -p "$restore_project" down
docker compose -p rescue-classroom up -d mysql redis
```

จดค่า `restore_project` หรือดูด้วย `docker compose ls` ก่อนเปลี่ยน shell ห้ามใช้ `down -v` ระหว่างการตรวจสอบ Redis เก็บสถานะออนไลน์ชั่วคราว ไม่ใช่ประวัติเหตุหลัก จึงไม่ต้องรวมใน backup ให้เจ้าหน้าที่กดเริ่มปฏิบัติงานใหม่หลังสลับ project

## แก้ปัญหาที่พบบ่อย

### ปุ่ม SOS กดไม่ได้

- ต้องเปิดผ่าน LINE LIFF และยืนยันตัวตนสำเร็จ
- เปิดสิทธิ์ตำแหน่งให้ LINE/เบราว์เซอร์และระบบปฏิบัติการ
- รอ **ได้รับตำแหน่งแล้ว** หากขึ้นข้อผิดพลาดหรือพิกัดหมดอายุ ให้กด **ขอตำแหน่งอีกครั้ง**
- ต้องมีเบอร์โทรก่อนเริ่มกดค้าง

### กด SOS แล้วไม่มีเจ้าหน้าที่เห็นงาน

- ตรวจว่าเจ้าหน้าที่ล็อกอินด้วย role `Rescue` ที่อนุมัติแล้ว
- ตรวจ `GPS ✓`, สถานะ **เปิดรับงานอยู่**, การเชื่อมต่อ Socket.IO และระยะไม่เกิน 50 กิโลเมตร
- ตรวจว่า Redis เชื่อมต่อได้ หาก Redis ล่ม เคสยังถูกบันทึกเป็น `Pending` แต่ยังจับคู่เจ้าหน้าที่ไม่ได้
- เปิดหน้า Admin เพื่อยืนยันว่าเคสอยู่ใน Active Events ก่อนส่งซ้ำ

### ข้อเสนองานหายหรือรับงานไม่ได้

- ข้อเสนอหนึ่งรอบมีอายุประมาณ 30 วินาที ระบบจะพยายามกระจายเคส `Pending` ใหม่
- เจ้าหน้าที่คนอื่นอาจรับก่อน ตรวจหน้า Admin ก่อนสร้างเคสใหม่
- อย่าเปิดบัญชี Rescue เดียวกันหลายอุปกรณ์พร้อมกัน

### หน้าติดตามไม่แสดงเส้นทางหรือเวลาโดยประมาณ

- ตรวจอินเทอร์เน็ตและการโหลด tile จาก OpenStreetMap
- OSRM สาธารณะอาจจำกัดคำขอหรือไม่ตอบชั่วคราว การรับงาน สนทนา และปิดภารกิจยังทำได้
- หากไม่มีตำแหน่งรถ ให้ตรวจ GPS และการเชื่อมต่อของอุปกรณ์เจ้าหน้าที่

### LINE Push ไม่เข้า

- ตรวจ LINE OA access token และการตั้งค่าในคู่มือส่งมอบ
- LINE UID จะมีเมื่อประชาชนยืนยันตัวตนผ่าน LIFF จริง
- ระบบค้นหา LINE UID จากเบอร์ประชาชนที่บันทึกไว้ เบอร์ในเคสและเบอร์ที่ผูกกับบัญชี LINE ต้องตรงกัน
- ใช้สถานะในแอปเป็นหลัก เพราะ LINE Push อาจไม่ทำงานเมื่อยังไม่ได้ตั้งค่า OA หรือผู้ใช้บล็อกบัญชีทางการ

### หน้าประชาชนหรือเจ้าหน้าที่ค้างหลังรีเฟรช

- หน้าประชาชนจะอ่าน Tracking ID และ token จาก local storage แล้วถามสถานะล่าสุดจาก backend
- หน้าเจ้าหน้าที่จะเรียกเคส `Accepted` ที่ผูกกับบัญชีนั้นกลับมาอัตโนมัติ
- ถ้าเคสยัง active ให้ปิดผ่าน **เสร็จสิ้นภารกิจ** หรือ **Force Cancel** ห้ามแก้สถานะด้วย SQL ระหว่าง backend ทำงาน

## เช็กลิสต์จบการสาธิต

- ปิดหรือยกเลิกทุกเคสให้ Active Events ว่าง
- ให้เจ้าหน้าที่กด **พักการรับงาน** และออกจากระบบ
- ออกจากระบบ Admin และปิด LIFF ที่ใช้เดโม
- ตรวจว่าไม่มีข้อมูลจริง รหัสลับ หรือไฟล์ backup ถูกเพิ่มเข้า Git
- หากต้องส่งฐานข้อมูลตัวอย่างใหม่ ให้สร้างจาก seed ตามคู่มือส่งมอบ ไม่ใช้ dump จากการสาธิตที่มีข้อมูลประชาชน
